Q-Learning

Space play · ←/→ tour · R reset

Q-learning gives every move in every square a number: how much reward it eventually leads to. The agent learns those numbers by trial and error, and the goal's reward seeps backward one square per visit.

    In the wild

    • DQN (DeepMind, 2015) swapped the table for a neural net and learned 49 Atari games from pixels, using this same max-Q target.
    • The TD error δ closely matches the firing of dopamine neurons: the brain seems to run a reward-prediction-error signal like this one.
    • Learned value functions with TD targets sit inside AlphaZero-style game engines, robot controllers and recommender systems that optimise long-term engagement.

    The update, after every single move

    Q(s,a) ← Q(s,a) + α·δ
    δ = r + γ·maxa′ Q(s′,a′) − Q(s,a)

    Latest move, –, with its real numbers:

    δ = – + – × – − – = –
    Q ← – + – × δ = –

    δ is the TD error, the surprise: what you got plus what the next square promises, minus what you expected. Positive δ nudges Q up, negative nudges it down. At a goal or pit there is no next square, so the target is just r.

    Choosing a move: ε-greedy

    a = random move, with prob. ε = –
    a = argmaxa Q(s,a), otherwise

    What it converges to

    V(s) = maxa Q(s,a) → γd−1·Rgoal
    start: d = –, γd−1R = –, learned –

    Exact when the step cost is 0 and the floor is solid; a step cost subtracts a little per move.

    Off-policy. The target uses the best next move, max Q(s′,·), not the move the agent will actually take. So it learns the optimal values even while acting at random (tour step 4), and it ignores its own exploration risk on the cliff (step 7). SARSA, which uses the move actually taken, learns the safer path.
    No map. The agent never "knows where the goal is". It has four numbers per square, and they change only when it visits. Move the goal and it must re-learn by experience (Try this #3).
