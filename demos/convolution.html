Convolution

Space play · ←/→ tour · R reset

A convolution slides one tiny grid of weights over an image and asks the same question at every position: “does this patch look like me?”

    In the wild

    • Every vision network — ResNet, YOLO, the image encoder inside multimodal LLMs — learns first-layer kernels that look strikingly like these Sobel-style edge detectors.
    • Vision Transformers start with a convolution too: a 16×16 kernel with stride 16 chops the image into patch tokens.
    • Phone cameras and photo apps run hand-set kernels (blur, sharpen, unsharp mask, edge-aware denoise) on the GPU for every frame.

    One output cell is a dot product

    y[i,j] = b + Σu,v∈{0,1,2} K[u,v] ·
             x[iS+u−P, jS+v−P]
    now: y[0,0] = 0  (b = 0)

    9 multiplies + 9 adds (8 for Σ, 1 for b) per cell. The amber kernel K and bias b are the only learned numbers — the same 10 are reused at every position (weight sharing), whatever the image size.

    Output size

    nout = ⌊(N + 2P − K) / S⌋ + 1
         = ⌊(18 + 2·1 − 3) / 1⌋ + 1 = 18

    Non-linearity and pooling

    a = max(0, y) = 0
    p[i,j] = max(a[2i‥2i+1, 2j‥2j+1])

    Coral = positive response, teal = negative. ReLU deletes the teal.

    Big output ≠ bright input. y is a dot product of patch and kernel, so it is large where the patch matches the pattern. The bright inside of the square gives exactly 0 under Sobel-x: nothing changes there.
    It is really cross-correlation. Deep-learning libraries do not flip the kernel the way textbook convolution does. For learned weights it makes no difference — the network simply learns the flipped kernel.

    Why depth helps

    The receptive field grows with every layer: 3×3 conv → 3 px, 2×2 pool → 4 px, another 3×3 conv on the pooled map → 8×8 px. Stacks of tiny kernels end up seeing whole objects.
