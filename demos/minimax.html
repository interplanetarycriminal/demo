Minimax + Alpha-Beta

Space play · ←/→ tour · R reset

A perfect game AI imagines every future, assumes you will answer perfectly, and backs the final scores up the tree — alpha-beta just skips the futures that cannot change its mind.

    In the wild

    • Chess engines (Stockfish) run alpha-beta to a depth limit, score the leaves with an evaluation function, and spend heavily on move ordering: hash moves, killer moves, iterative deepening.
    • AlphaZero / MuZero swap brute force for Monte-Carlo tree search guided by a network: the policy head is a learned move order, the value head a learned leaf score.
    • The same max–min shape trains GANs and adversarially robust models: one player maximises a loss the other minimises.

    Minimax value

    V(s) = u(s)  if the game is over
    V(s) = maxm V(s+m)  if the AI moves
    V(s) = minm V(s+m)  if you move

    u(s) is the final score: +1 AI wins, 0 draw, −1 you win. Exact value of the searched position: –. The empty board is worth 0 — a draw.

    Alpha-beta window

    α = best the AI can already force
    β = lowest you can already force
    stop searching a node once α ≥ β

    Last cut: α = –, β = –, –. A cut value is only a bound: “≤0” means “no better than a draw for the AI”.

    Cost

    plain minimax ≈ bd = –
    ideal α-β ≈ bd/2 ≈ √(bd) = –
    best-first (oracle) = –
    your setting = –

    b = moves per turn, d = plies to the end. Tic-tac-toe’s branching shrinks every ply, so √ is only a rough guide. Best-first can even lose to the heuristic: many moves tie on value and it breaks ties by square order, while the heuristic grabs an immediate win, which refutes a line in a single node.

    Alpha-beta is not an approximation. It returns exactly the minimax value and the same best-move value; it only skips branches that provably cannot change the answer.
    “Perfect” means perfect against a perfect opponent. Minimax is pessimistic: it cannot tell a safe draw from a draw that sets you a trap.
